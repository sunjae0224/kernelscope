# GPGPU-Sim으로 본 KV 분할 수와 부하 불균형 (2026-09-26)

GPU가 없는 노트북에서 사이클 수준 시뮬레이터 GPGPU-Sim 4.2(구성 SM7_QV100, SM 80개)로, 실측에서 추정한 부하 불균형 기전을 다른 방법으로 확인했다. 실행 환경과 커널 소스는 `experiments/gpgpusim/`(README에 CUDA 11.8 우회 규칙)에 있고, 원본 수치는 [gpgpusim-splitkv-sweep.csv](gpgpusim-splitkv-sweep.csv)에 있다. 이 문서의 수치는 `kernelscope verify`의 `sim.*` 항목으로 재계산된다.

**커널.** fp32, d = 64, GQA(질의 8 / 키·값 2), B = 16. 그리드 (S, B, H_q); 분할 s는 캐시 용량(최대 길이) 기준으로 자른 키 구간을 맡으므로 짧은 요청의 뒤쪽 분할은 일을 하지 않는다(FlashAttention-2와 같은 규칙). 워프 4개가 키를 나누어 온라인 softmax를 계산하고, S > 1이면 두 번째 커널이 부분 결과를 합친다. CPU 배정밀도 참조와의 최대 오차는 2e-8이다. B × H_q = 128 = 0.8 × 2 × 80이므로 FlashAttention의 휴리스틱이라면 두 배치 모두 "이미 가득 찼다"고 보고 S = 1을 고르는 조건이다.

| 배치 | S=1 | S=2 | S=4 | S=8 | S=16 | S=1 대비 최대 개선 |
|---|---:|---:|---:|---:|---:|---:|
| 혼합 길이 2048 + 128×15 (사이클) | 452,140 | 230,648 | 121,071 | 86,491 | 62,566 | **7.23배** (S=16, 계속 감소) |
| 균일 길이 256×16 (사이클) | 53,004 | 31,388 | 24,515 | 23,506 | 26,102 | 2.25배 (S=8, S=16부터 악화) |
| 혼합 길이 IPC | 104.8 | 211.2 | 424.8 | 657.2 | 1,081.7 | |
| 균일 길이 IPC | 921.4 | 1,611.9 | 2,206.8 | 2,599.8 | 2,878.7 | |

**해석.** 두 배치의 키 총량은 거의 같다(3,968 vs 4,096). 그런데 S = 1에서 혼합 길이 배치는 균일 배치보다 **8.5배** 오래 걸리고 IPC는 1/9이다. 긴 요청 하나를 맡은 CTA 8개가 2,048개 키를 순차 처리하는 동안 나머지 SM이 노는 부하 불균형이 사이클 수준에서 그대로 나타난다. 분할 수를 늘리면 혼합 길이 배치는 명령어 수가 43% 늘어남에도 S = 16까지 계속 빨라지고, 균일 배치는 S = 8에서 포화한 뒤 결합 비용 때문에 다시 느려진다. RTX 4090 실측(혼합 길이 최악 12.53배 vs 균일 길이 손실 0.7%)과 같은 방향이다.

**한계.** 이 축소 커널은 CTA당 워프 4개뿐이라 S = 1에서 균일 배치도 SM을 다 채우지 못해 분할로 2.25배를 얻는다. 실제 FlashAttention-2 커널은 CTA 하나의 병렬성이 크고 텐서 코어를 쓰므로 균일 배치의 이득이 거의 없다. 따라서 이 결과는 "혼합 길이에서 분할 수가 훨씬 중요하다"는 정성적 재현이며, 절대 사이클이나 최적 분할 수를 실측과 맞춘 것은 아니다. 시뮬레이터에서는 `-lineinfo`(PTX `.loc … inlined_at` 파싱 실패)와 `__shfl_xor_sync`(결과 오차 8.6e-3)를 피했다.
