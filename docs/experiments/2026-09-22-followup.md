# 후속 검증: 선택 비용, 자연어 입력, 두 모델

**모델 정책의 실행 비용을 줄였고, 기존 선택표에 없는 배치·문맥 구성에서 두 모델의 혼합 길이 이득을 확인했다. 모든 조건에서 유리하거나 출력이 동일한 정책은 아직 아니다.**

## 구현과 실험

- 같은 이벤트 계산을 수행하는 선택적 C 시뮬레이터를 추가했다. 기존 혼합 배치의 첫 정책 선택은 842.600 → 14.293ms로 줄었으며, 검증한 7개 구성의 후보 예측값과 순위는 동일했다. 별도의 최초 빌드 비용은 55.683ms다. [CPU 실험](2026-09-22-policy-latency.md)
- 직접 작성한 자연어 문단으로 uniform/ragged/arrivals를 구성했다. B28, 짧은 문맥 384, 긴 문맥 12,288토큰이며 기존 선택표 211행에 B28이나 Lkv12,288 조건은 없다. 표와 피팅 계수는 재학습하지 않았다.
- Qwen3-4B-Instruct-2507와 DeepSeek-R1-Distill-Llama-8B, 시드 0·1, 세 정책, 세 반복으로 최종 **108회** 측정했다. 모델·시드·데이터·구현이 다른 결과는 합산하지 않는다.
- 각 정책으로 전체 시나리오를 한 번 워밍업하고, 측정 때는 정책 객체와 KV를 새로 만든다. 따라서 첫 선택·새 페이지 구성 예측 비용도 포함한다.
- Llama도 독립 Hugging Face 구현과 prefill·decode 두 단계의 비교를 통과했다. 세 비교의 최소 cosine은 0.999805이고 top1은 같았다. 이 짧은 입력 검증을 장문 생성 전체의 동등성으로 확대하지 않는다. [원본](llama8b-validation.json)

TPOT는 요청별 평균 토큰 간격이며, 새 요청의 직렬 prefill 대기와 정책 선택을 포함한다. 균일 배치에서 표 기반 선택은 거의 차이가 없었고, 모델 선택은 약 1–2% 느렸다. 실측표의 ragged 두 조합, 두 모델의 arrivals 모든 조합은 출력 불일치로 성능 개선 주장 대상에서 제외했다. 전체 비교 정책·입력 조합의 출력 검증 통과는 **14/24**다. 이것이 모두 속도 개선이라는 뜻은 아니다.

## 예비 측정과 워밍업 보완

첫 108회는 요청당 decode 두 스텝으로 워밍업을 제한했다. Arrivals에서는 요청이 다음 합류 전에 끝나 B4까지만 워밍업됐고, 본 측정의 B8~B28을 경험하지 못했다. Qwen arrivals seed 0 휴리스틱의 반복 표준편차가 9.366ms였으므로 전체 흐름 워밍업으로 108회를 다시 측정했다. 보완 후 해당 표준편차는 0.030ms였다. 이 비교만으로 이전 변동의 원인이 전부 워밍업이었다고 단정하지 않는다.

예비 결과를 삭제하지 않았으며 [별도 보고서](followup-pilot/README.md)와 대시보드의 `followup_20260922` 캠페인에 남겼다. 최종 성능 해석은 `followup_fullwarmup_20260922`를 사용한다.

예비·최종 측정의 108개 실행 쌍은 생성 토큰 배열이 모두 동일했다. 프롬프트 해시, 공통 코드 22개의 해시, 고정 정책 입력도 대조했다. 워밍업 보완이 출력 불일치를 없앤 것은 아니다.

## 출력 불일치 진단

Qwen arrivals seed 0을 같은 휴리스틱 토큰 이력으로 재생했다. 55개 decode 호출, 정책당 868개 로짓 벡터를 비교했고 모든 값은 유한했다. 모델·표 정책 모두 argmax는 866/868개에서 같았다. 다른 토큰은 기준에서 순위 2였고 기준 top1과의 간격은 0.125 또는 0.250이었다. 최소 cosine은 모델 0.999036, 표 0.998497이었다. 모든 불일치가 정확한 동점으로만 발생한 것은 아니다.

작은 수치 차이가 greedy 선택을 바꾸고 이후 자유 생성의 차이로 이어질 수 있음을 보여준다. 이 진단으로 자유 생성 출력 불일치를 통과 처리하거나 답변 품질이 같다고 주장하지 않는다. [원본 로짓 통계](heldout-arrivals-numerics/teacher_forced_logits.csv) · [입력 해시와 재현 설정](heldout-arrivals-numerics/manifest.json)

CSV의 cosine은 float32 계산의 반올림으로 일부 값이 1을 약 0.000008 초과한다. 원본 값을 보존했으며 이를 수학적으로 1보다 큰 유사도로 해석하지 않는다.

## 졸업 프로젝트로서의 의미

단순히 빠른 커널을 찾는 데서 나아가, **병목 발견 → 선택 비용 최적화 → 두 모델의 전체 생성 검증 → 실패 조건과 원인 분석**을 연결했다. 긍정·부정 결과와 예비 실험의 보완 과정까지 재현할 수 있다.

두 모델의 head 구성은 같고 GPU도 RTX 4090 한 대다. 입력은 직접 구성한 문단이며 운영 트래픽이나 표준 언어 품질 평가가 아니다. HTTP 부하, 운영 서버 스케줄러, CUDA Graph, 다른 GPU에 대한 이득은 별도로 검증해야 한다.

최종 CPU 테스트는 **462개 통과, 4개 skip, GPU 12개 제외**다. 오프라인 wheel 빌드와 C 소스 포함도 확인했다. GPU 단위 검증의 기존 7개 통과 기록에 더해 이번에는 두 모델의 실제 전체 생성 캠페인과 독립 Llama 수치 검증을 수행했다.
