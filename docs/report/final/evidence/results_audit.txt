## 보고서 포지셔닝의 증거 범위

현재 브랜치의 실증 성과는 **프로파일링·시뮬레이션 분석 환경과 실측 대리 성능 모델을 보강하고, 혼합 길이 디코드 배치의 정적 설정 손실을 관측해 매 단계의 KV 분할 수/attention 변형 선택으로 TPOT을 줄인 것**이다. 사이클 시뮬레이터 upstream 자체를 개선했다거나, 실제 관측이 없던 현상을 본 작품이 최초 발견했다거나, 새로운 요청 스케줄링 알고리즘을 개발했다고 쓰면 근거보다 강하다. README·`docs/graduation.md`도 새 GPU 시뮬레이터·새 attention 수식이 기여가 아니라고 명시한다.

- 선택에 직접 쓰는 것은 실측 테이블과 실측으로 맞춘 대리 성능 모델이다. Accel-Sim/GPGPU-Sim은 원인 설명·자원 민감도 분석·축소 커널의 정성 검증이다. Accel-Sim 절대 시간 보정은 완료되지 않았다.
- 요청 admission은 FIFO 연속 배치다. 구현된 최적화는 커널 내부 작업 분배에 영향을 주는 KV 분할 수 및 변형의 외부 선택이다. 새 요청 순서/배칭 스케줄러를 만들었다고 서술하지 않는다.
- ‘개선된 시뮬레이터’라는 표현이 필요하면 대상이 **시뮬레이션을 포함한 분석 파이프라인과 대리 성능 모델**임을 문장에서 정확히 한정한다.
- FA2 2.8.x, 실제 환경 2.8.3.post1; 직접 FlashInfer 비교는 0.6.13; vLLM0.31은 별도 환경의 FlashInfer0.7.0.post1; RTX4090 SM89 128SM이다. Hopper/FA3, 다중 GPU, 일반 서비스 전체에 일반화할 수 없다.

## vLLM정정및보정집계

10/6실행은`VLLM_ATTENTION_BACKEND`라는vLLM0.31에서지원하지않는환경변수를썼다. 번들`demo_data/vllm_4090/backend_selection.json`에는엔진8회모두FLASH_ATTN,경고8회,FLASHINFER요청4회가기록된다. 따라서‘백엔드무관0.997배’는철회한다. 중간v2의0.997은자체엔진균일조건의배율이므로이와혼동하여철회하지않는다(그수치는별개다).

새프로파일의`manifest.json`도`engine_reported_backend=null`이다(로그regex불일치). 실제backend변경은상위커널이름과서버로그에기반한다. 이작업에서는번들`step_breakdown.json`의커널및iteration자료를확인했다.

원래`summary`열별중앙값은forward/sampling주석iteration을혼합해잘못된step값이다. `analysis/vllm_steps.py`와동일한방식으로배치32decode행커널합을step당커널수로나눈후GPU시간을독립재집계했다. JSON의`vllm.corrected_rows`가정확값이다.

혼합−균일step차이의97.6%가attentionGPU시간차이이다. 백엔드효과는있다(FA2혼합81ms,FlashInfer36ms). 그러나vLLM에서분할수를바꾸어재실행한직접인과실험은없다. FA2래퍼는num_splits0/1만허용하여외부분할선택을그대로통합하지못한다. ‘운영엔진에본정책적용완료’또는‘vLLM81→31ms달성’은주장불가다.

FlashInfer의`use_tensor_cores=False`가라이브러리기본값이다. ‘GQAgroup≥4일때TC’는SGLang기준, vLLM0.31은group과무관하게항상True다. FlashInfer라이브러리전체가정적기본값을고집한다고쓰면부정확하다(내부길이적응스케줄러도있음). 근거문서:`docs/report/final/related_work_additions.md`C절.

대응검사: `vllmbackend.*`, `p3vllm.<run>.{unprofiled_ms|attention_ms|...}`, `p3vllmx.*`, `p3vllm.excess_share.{fa2|fi}`, `p3vllm.after_leave.attention`, `p3vllm.logged_median.attention`(오류값보존검사용이며보고서성능수치로사용금지).

## 추가검사요청여부

보고서가위표의기존수치만사용하면대부분기존검사로커버된다. JSON의`existing_verify_literal_keys`는소스에서정적으로추출한정확키목록이다. comprehension생성키는위패턴에포함한다. JSON행의`verify_speedup_key`는의미상매핑보조이며heuristic기준행에는개별속도검사가없을수있다.

새로운TPOT감소율(44.83%,59.17%,3.35%)이나처리량증가율2.81%를본문대표수치로쓰면기존TPOT/처리량으로부터계산한파생수치이므로,보고서전용검사에서이산식을직접검사하면좋다. 새실험은필요없다. hybrid트레이스평균배율0.9692와baselineTPOT새표의절대값에전용검사가없는경우도같은보고서전용검사로충분하다.
