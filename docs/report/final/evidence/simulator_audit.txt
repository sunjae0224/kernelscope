# design-1-3 시뮬레이터·성능모델 감사

감사 대상: `/root/sunjae/gpu_graduation/kernelscope`, `design-1-3` 최신 커밋 `4cdd4fd`. 수행 범위: 코드와 저장된 실험·설정·검증 규약의 읽기 전용 점검. 새 GPU 실험, pip, pytest, 빌드는 수행하지 않았다. 저장된 성능 수치는 해당 캠페인의 기록이며 이번 감사에서 재측정한 값이 아니다.

## 1. 보고서 포지셔닝 결론

사용자의 중심 축인 **시뮬레이터 개선 → 기존 평가에서 놓친 엣지 케이스 관측 → 분할·선택 알고리즘으로 TPOT 개선**은 다음 범위로 구체화하면 코드와 일치한다.

> 본 작품은 LLM 디코드 attention의 요청별 KV 길이와 CTA 실행 구조를 반영하는 성능 분석·시뮬레이션 환경을 구축하고, 자체 이벤트 기반 성능 시뮬레이터의 계산 비용을 개선하였다. 이를 실측 프로파일링 및 사이클 수준 시뮬레이션과 결합하여 균일 길이 평가에서 드러나지 않는 혼합 길이 배치의 부하 불균형을 분석하였다. 분석 결과를 바탕으로 모델과 배치 순서를 유지한 채 KV 분할 수 및 커널 변형을 선택하고, attention 실행 시간과 실제 모델 생성의 TPOT 변화를 함께 평가하였다.

순서의 인과관계도 유의해야 한다. `PLAN.md`와 실험 노트는 현상을 **RTX 4090 실측으로 진단**하고, 자체 모델·GPGPU-Sim으로 원인을 설명하며, 트래픽 모델로 빈도를 추정한 흐름을 명시한다. “개선된 GPGPU-Sim이 최초로 문제를 발견하였다”는 서사는 증거와 맞지 않는다. “기존 균일 길이 중심 평가에서 드러나지 않던 사례를 실측·시뮬레이션으로 관측하였다”는 표현은 가능하다. 문헌 전체에서 선행 발견이 없다는 신규성 주장은 이 리포만으로 입증할 수 없다.

## 2. 반드시 구분할 세 종류의 시뮬레이션

| 구성 | 실제 구현/변경 | 실험에서 담당하는 역할 | 주장 가능한 성과 | 주장하면 안 되는 것 |
|---|---|---|---|---|
| 자체 CTA 이벤트 기반 대리 성능 시뮬레이터 | `kernelscope/model/{geometry,simulate,predict,fit,machine,params}.py`, `_simulate_native.c`, `_simulate_backend.py` | 요청별 길이→CTA 작업량→자원 제한·대역폭 공유→후보 실행 시간 및 분할 순위 | 혼합 길이/캐시/CTA 배치 반영, 실측 보정, CPU 계산 비용 절감 | 명령어 단위 GPU 시뮬레이터, 범용 GPU 정확도 보장, C 경로가 예측 정확도를 높였다는 주장 |
| GPGPU-Sim 4.2 | upstream 소스 **무수정**. `experiments/gpgpusim/run_sim.sh` 실행 우회·축소 커널 작성 | split-KV 부하 불균형 기전의 사이클 수준 정성 재현 | 혼합 배치가 분할로 크게 개선되고 균일 배치는 먼저 포화함을 재현 | FlashAttention-2 전체 구현의 절대 시간 보정, RTX 4090 실측과 최적 분할 수 일치 |
| Accel-Sim v2.0.0 + SM89_RTX4090 자원 설정 | RTX 4090 설정 파생, NVBit 추적/재생/what-if 자동화, **기존 Ampere opcode map에 binary version 89를 연결하는 작은 호환 패치 존재** | 하드웨어 자원 민감도와 미보정 모델 한계 진단 | 실행 가능한 Ada 공통 opcode 부분집합 재생, 검증 실패 및 캐시 매핑 문제 발견 | 완전한 Ada ISA 구현, RTX 4090 타이밍 보정 완료, 메모리 분할 해시 문제 수정 완료 |

중요: `CLAUDE.md`는 upstream 직접 수정을 금지하는 현재 작업 규칙이다. 하지만 기존 결과 기록 `docs/setup/accelsim_4090_gate_report.md`와 추적된 `docs/setup/accelsim-sm89.patch`는 연구실 Accel-Sim 트리에 과거 sm_89 호환 패치가 적용되었음을 명시한다. 따라서 보고서에 “모든 upstream 시뮬레이터를 전혀 수정하지 않았다”라고 쓰면 안 된다. **GPGPU-Sim 무수정, Accel-Sim에는 제한된 호환 패치**라고 정확히 적는다.

## 3. 자체 시뮬레이터의 구체적 구현

### 입력과 실행 구조

- 지원 범위는 decode `L_q=1`, head dimension 128, fp16/bf16이다(`geometry.check_scope`).
- 각 요청의 실제 KV 길이, GQA head 구성을 받아 nonsplit/split/split_paged 실행을 구분한다.
- FlashAttention 2.8.3 `num_splits_heuristic`을 포팅하여 정적 기본값을 재현한다(`geometry.num_splits_heuristic`, `resolve_splits`).
- dense/paged 최대 캐시 용량을 기준으로 KV 분할 범위를 계산하고, 짧은 요청의 뒤쪽 빈 CTA도 모델에 포함한다(`build_launch`).
- 스레드·레지스터·공유메모리 사용량을 통해 SM당 상주 가능한 CTA 수를 계산한다(`predict`, `KIND_RESOURCES`).
- 실제 CTA 배치 탐침에서 관측한 짝수 SM→홀수 SM 순서와 SM당 CTA 2개 공존 시 처리율 계수 γ를 사용한다(`MachineSpec.sm_order`, `KindParams.gamma`).
- 시작 고정 비용/빈 CTA 비용/키 스트리밍을 구분하고, 활성 CTA의 요구량 합이 전체 대역폭을 넘으면 처리율을 함께 축소하는 이벤트 기반 processor sharing 모델이다(`simulate.py`).
- cold 상태는 실측 DRAM 대역폭, warm 상태는 실측 L2 hit 곡선과 DRAM/L2 상한을 반영한다. combine kernel 비용은 `a + b × B × H_q × splits` 항으로 추가한다.
- 기계 상수는 실측 JSON(`machines/rtx4090.json`), 커널 비용 계수는 캐시 상태·커널 종류별 피팅(`models/rtx4090.json`)으로 분리한다. SM 수·DRAM·L2·공유메모리 변화 what-if는 `MachineSpec.scaled`가 제공한다. what-if는 검증 전까지 예측이다.

### 계산 비용 개선

`docs/experiments/2026-09-22-policy-latency.md`와 `_simulate_native.c`가 근거다. NumPy 기준 구현을 보존하고 동일한 이벤트·CTA 입장·임계값·합산 순서를 C로 구현했다. `-fno-fast-math -ffp-contract=off`를 사용하고, 컴파일러 부재/실패 시 Python 기준으로 되돌아간다. import 시 컴파일하지 않으며 `prepare_simulator()` 준비 비용을 정책 결정 시간과 별도로 기록한다.

| 첫 선택 구성 | NumPy 기준 | C 경로 | 비용 감소 배율 |
|---|---:|---:|---:|
| Uniform | 1,068.881 ms | 18.926 ms | 56.5배 |
| Ragged | 842.600 ms | 14.293 ms | 59.0배 |
| Arrivals 혼합 배치 | 348~963 ms | 6.468~17.213 ms | 53.8~59.1배 |
| 마지막 단일 요청 | 4.824 ms | 0.519 ms | 9.3배 |

구성마다 새 정책 객체, 5회 중앙값, 교대 순서 측정이다. 캐시 hit 0.902~5.567 μs. 최초 빌드/로드 55.683 ms, 기존 바이너리 로드 1.537 ms는 첫 선택에서 제외하고 별도 보고했다. 7개 실제 구성에서는 모든 후보 예측 시간 차이 0, 순위·분할 선택 동일. 기록된 무작위 등 220개 검증은 환경·입력 범위의 동작 검증이지 모든 CPU/컴파일러에서 비트 동일 보장이 아니다.

**해석:** “시뮬레이터 계산 경로 최적화”의 확실한 근거이다. 정확도 또는 모델 자체의 선택 품질을 개선한 결과는 아니다. 특히 C 경로도 새로운 페이지 구성에서 수 ms의 결정 비용이 남는다.

### 정확도와 선택 품질

`docs/plan/2026-09-22-model-validation.md`:

| 집합 | n | 중앙값 APE | p90 APE |
|---|---:|---:|---:|
| V1 cold | 594 | 9.0% | 22.5% |
| V1 warm | 594 | 2.3% | 13.3% |
| V5 cold | 882 | 12.3% | 32.1% |
| V6 cold | 1,971 | 11.1% | 20.2% |

이는 **APE 중앙값**이며 MAPE 2.3~12.3%라고 쓰면 안 된다. 모델 단독의 최악 선택 regret은 V1 cold 24.3%, V1 warm 41.7%, V5 cold 66.3%, V6 cold 24.5%로 목표 15%를 실패한다. 실행 시간 오차가 작아도 근접한 후보의 순위가 뒤집힐 수 있다.

`docs/experiments/2026-09-26-hybrid-policy.md`의 모델·테이블 혼합(δ=0.2)은 leave-one-out **cold 세 집합** 최악 regret을 1.97%/7.54%/10.90%로 줄인다. warm V1 최악 41.7%는 여전히 실패한다. V5는 같은 head 구성의 별도 측정 격자를 요구하고, 격자가 없으면 모델 단독으로 되돌아간다. V6에는 특징 거리 0의 이웃이 있는 셀이 219개 중 39개여서 성긴 운영 테이블 일반화에 제약이 있다.

## 4. GPGPU-Sim 결과의 정확한 범위

소스: `experiments/gpgpusim/{README.md,splitkv_attn.cu,run_sim.sh}`, `docs/experiments/2026-09-26-gpgpusim-splitkv.md`, `gpgpusim-splitkv-sweep.csv`.

- GPGPU-Sim 4.2.0 dev `a4ce3fe`, SM7_QV100, SM 80개, CUDA 11.8. RTX 4090/Ada 설정이 아니다.
- fp32, d=64, B=16, H_q=8/H_kv=2의 직접 작성한 축소 split-KV 커널, 128 threads/CTA, 온라인 softmax 및 partial combine. CPU double 참조 대비 최대 오차 약 2e-8.
- 혼합 KV 2048+128×15: S=1 **452,140 cycles**, S=16 **62,566 cycles** → **7.23배**.
- 균일 KV 256×16: S=1 **53,004 cycles**, S=8 **23,506 cycles** → **2.25배**, S=16에서는 **26,102 cycles**로 악화.
- 키 총량은 3,968 대 4,096으로 비슷하지만 S=1 혼합 길이는 균일 대비 약 8.5배 느리다.
- 실제 FA2는 텐서 코어와 더 큰 CTA 내부 병렬성을 사용한다. 축소 커널은 균일 배치도 분할로 2.25배 개선되어 실측과 절대 크기가 다르다. **기전의 정성 재현**으로만 사용한다.
- 실행 호환성은 `CUOBJDUMP_SIM_FILE=1`, uncompressed fatbin/PTX 추출 등 스크립트로 해결했다. `-lineinfo` 파싱 실패와 `__shfl_xor_sync` 기능 오차(8.6e-3)를 우회하여 shared memory 합산을 사용했다. 이 문제를 시뮬레이터에서 고쳤다고 쓰면 안 된다.

## 5. Accel-Sim 확장과 미완료 보정

소스: `docs/setup/accelsim_4090_gate_report.md`, `docs/setup/sm89_rtx4090_config.md`, `docs/setup/SM89_RTX4090/`, `docs/setup/accelsim-sm89.patch`, `kernelscope/backends/accelsim/`.

### 구현된 내용

- RTX 3070의 SM86 자원·타이밍 설정에서 RTX 4090 자원 모델 파생: 128 SM, 활성 L2 72 MiB, 384-bit memory bus, SM당 24 CTA, block당 opt-in shared memory 99 KiB, nominal core 2520 MHz.
- HMMA latency·DRAM timing 등은 Ampere 부모 모델 계승. 새 Ada 세대의 전체 타이밍을 측정·보정한 모델이 아니다.
- 패치는 `gpu-simulator/trace-driven/trace_driven.cc`의 opcode-map 분기에서 binary version 89를 기존 Ampere opcode map으로 보낸다. unknown opcode 실패는 남는다. “Ada 지원 완성”이 아닌 **공통 명령어 부분집합의 replay 호환**이다.
- NVBit의 warm-up/JIT를 제외한 한 실행만 추적하는 window 제어, 정확한 커널 필터링, 추적량 기반 예산·skip, stdout/stderr/clean-exit sentinel 검사, trace 1회 후 7개 자원 변형 재생, long-format 결과/메타데이터 저장을 구축했다.
- `config.py`의 7 변형은 base, L2 ×2/½, DRAM clock(대역폭) ×2/½, SM ×2/½이며 각 변형은 1개 설정만 바꾼다.
- 6 attention cells ×7 = 42 replay 및 naive base 1개가 clean exit로 완료했다. 기능적 실행 성공은 시간 정확도 성공과 다르다.

### 정확도와 관측된 한계

nominal 2520 MHz 변환 `sim_us=cycles/2520`, 실측 profiler kernel 시간 대비 비:

| 커널/조건 | 실측 μs | simulated μs | sim/real |
|---|---:|---:|---:|
| FA2 B1 L1K | 63.584 | 67.465 | 1.061 |
| FA2 B1 L8K | 494.336 | 515.940 | 1.044 |
| FA2 B16 L1K | 64.303 | 109.735 | 1.707 |
| FlashDecoding B1 L1K | 10.016 | 15.507 | 1.548 |
| FlashDecoding B1 L8K | 27.456 | 73.591 | 2.680 |
| FlashDecoding B16 L1K | 38.2235 | 116.809 | 3.056 |

FA2 B1만 목표 0.7~1.4 통과. 다른 attention cells은 실패한다. 공식 표는 **1.044~3.056** 범위이며 PLAN의 “1.05~3.06”은 반올림 요약이다. 따라서 Accel-Sim 정확도가 5% 수준이라고 표현할 수 없다.

후속 설정 탐침: host launch delay 제거 + 저장된 target launch 1회 warm-up은 FD B1 L1K/L8K 비를 0.831/1.054로 바꾸었으나, B16은 FA2 1.470, FD 3.039로 실패했다. 추적의 async HtoD 복사 누락 및 초기 cold cache가 비교 불일치에 기여하며, warm-up 규약 수정만으로 일반화하지 못했다. 이 값은 공식 baseline을 대체하지 않는다.

기존 partition indexing mode 2가 64 hash slots를 `%48`하여 48 L2 subpartition 중 0~15에 두 배의 주소를 배정하는 문제가 관측되었다. FD B16 실재생 counter는 그룹별 read/slice **2.003배** 차이. 이는 **시뮬레이터 설정의 mapping artifact**이며 실제 RTX 4090의 하드웨어 문제라는 증거가 아니다. 대안 mode 6(IPOLY_MODULO)는 후보로만 제시되어 있고 통제 재검증은 미완료이다. “L2 hash 개선으로 RTX 4090 시뮬레이터 정확도 향상”이라고 쓸 수 없다.

SM ×2가 FD B16을 오히려 59% 늦게 만드는 등 자원 what-if 결과는 미보정 모델 내부 민감도이다. 실제 GPU 증설/설계의 속도 예측으로 단정할 수 없다.

## 6. ‘스케줄링/알고리즘’의 보고 범위

`kernelscope/serve/engine.py`는 FIFO admission, 일정한 논리적 도착 step, 최대 batch 64, 요청 종료까지의 KV 페이지 예약을 가진 단일 프로세스 continuous batching 실험기다. 모든 정책이 같은 요청 스케줄과 배치 순서를 본다. 새로운 admission/priority/요청 재정렬/멀티 GPU 스케줄러를 구현하여 성능을 개선한 것이 아니다.

실제 최적화 단위는 **KV 분할을 통한 CTA 작업 분배와 step별 커널 구성 선택**이다. `serve/dispatch.py`가 heuristic(0), fixed N, nearest table, surrogate model, hybrid, table_any를 제공한다. Table의 특징은 log2(batch, max KV, mean KV), 모델 cache는 head 구성과 순서를 보존한 256-token 페이지 수 벡터이다. backend 전환 표는 layer당 kernel time × layer 수에 FlashInfer step당 plan 비용을 더해 후보 비용을 비교할 수 있다.

보고서에는 “커널 실행 구성을 결정하는 스케줄링 정책” 또는 “KV 작업 분할·동적 선택 알고리즘”이라고 구체화한다. “기존 서비스 스케줄러보다 우수한 새 요청 스케줄러”라고 쓰면 안 된다.

## 7. TPOT 결과의 핵심 조건과 한계

부모 에이전트의 성능 감사와 함께 사용할 교차 확인용이다.

- 2026-09-22 Qwen3-4B 32K×1+512×31: table TPOT **61.06→33.80 ms, 1.81배**. 초기 합성 토큰 조건이며 동일 실험 5회에서 토큰 일치.
- 최신 2026-10-24 fixed baseline: 32K table **1.813배**, fixed16 **1.804배**, fixed8 **1.811배**(이상치 1회 제외; 포함 시 1.644배). 64K table **2.448배**, fixed8 **2.443배**, fixed16 **2.429배**. 동적 정책이 고정 분할보다 TPOT에서 확실히 우월하다는 근거는 없다.
- 고정 분할은 warm 균일 길이 격자에서 fixed8 최대 **1.712배** 손실로 cold 결론과 달라진다. 따라서 조건과 출력 보존을 함께 비교해야 한다.
- held-out 요청 도착에서 hybrid는 table 대비 attention 3.31→3.00 ms/step이지만 실행마다 cache reset 규약에서는 결정 비용 때문에 TPOT 배율 hybrid 1.020배, table 1.085배. cache keep에서는 hybrid 1.090배, model 1.091배, table 1.086배.
- Azure conv 실트레이스의 단순화 모델은 regret≥1.25 step **13.5%**를 예측, 층화 커널 표본은 **8.9%(95% 6.3~10.9%)**로 추정한다. 예측·실측 regret 순위 상관 **0.959**. 13.5%를 관측값처럼 쓰면 안 된다.
- Azure conv 일부 요청 550..849, 1,897 decode steps, 평균 batch 26.9의 실제 engine replay에서 table TPOT **1.035배**, 처리량 **+2.8%**. model/hybrid는 빈 cache 첫 반복 **약 0.86배**; 이후 keep cache 반복에서는 **1.035~1.037배**. 실제 트래픽 전체에서 항상 1.8~2.4배라고 일반화하면 안 된다.
- 출력은 수학적으로 같은 attention이라도 bf16 연산 순서와 KV 오차 증폭으로 토큰이 달라질 수 있다. “답이 항상 유지된다/토큰 불일치는 모두 tie이다”는 거짓이다. 분기 사건 수·tie/clear 분류와 같은-KV kernel probe를 보고해야 한다.
- vLLM 0.31의 2026-10-06 ‘backend 무관 0.997배’ 결론은 두 실행 모두 FLASH_ATTN이어서 근거가 없다. 최신 10-24 프로파일은 attention GPU 시간이 혼합/균일 step 차이의 **97.6%**를 설명하고 FlashInfer backend 혼합 step을 **81.0→36.0 ms**로 줄인다. 하지만 외부 num_splits 선택은 vLLM wrapper가 0/1만 허용하므로 직접 이식 검증되지 않았다.

## 8. 최종보고서에 바로 사용할 요약 문단

### 목적·구현

본 작품은 혼합 길이 LLM 디코드 배치의 attention 실행을 분석하기 위하여 GPU 실측 프로파일링, 사이클 수준 시뮬레이션, 자체 이벤트 기반 성능모델을 연결하였다. 자체 모델에는 요청별 KV 길이, CTA 작업 분할, SM 자원 제한, 메모리 대역폭 및 캐시 상태를 반영하였다. 또한 NumPy 기반 이벤트 계산을 동일한 동작의 C 경로로 개선하여 검증한 구성에서 최초 커널 선택의 CPU 비용을 9.3~59.1배 줄였다. GPGPU-Sim은 축소 split-KV 커널의 부하 불균형을 확인하는 데 사용하였으며, Accel-Sim에는 RTX 4090 자원 설정과 제한된 sm_89 재생 호환성을 추가하였다.

### 관측·개선

균일 길이 배치에서는 작은 차이로 보이던 정적 커널 설정의 손실이 긴 요청과 짧은 요청을 함께 처리할 때 커질 수 있음을 확인하였다. 전체 CTA 수가 충분하더라도 긴 요청을 담당하는 일부 CTA에 작업이 집중되기 때문이다. 이를 완화하기 위하여 배치 순서를 유지한 채 KV 분할 수와 커널 변형을 선택하는 정책을 구현하였다. 통제된 32K·64K 혼합 길이 조건에서는 기본 휴리스틱 대비 TPOT가 각각 약 1.81배·2.45배 개선되었다. 공개 트레이스를 이용한 일부 요청 재생에서는 약 1.035배로 개선 폭이 작아져, 효과가 요청 길이 분포와 배치 상태에 의존함을 확인하였다.

### 결론·한계

본 결과는 시뮬레이터의 범용 정확도 향상이나 새로운 attention 수식의 제안이 아니라, 분석 환경의 확장과 계산 비용 개선을 바탕으로 취약한 실행 조건을 식별하고 기존 커널의 실행 설정을 조정한 시스템 구현 결과이다. Accel-Sim의 RTX 4090 타이밍 모델에는 보정 오차가 남아 있으며, 동적 선택의 TPOT가 고정 분할보다 일관되게 우수하지는 않았다. 따라서 성능 개선 배율뿐 아니라 정책 결정 비용, 고정 분할 기준선, 캐시 상태와 출력 분기까지 함께 평가하여 적용 가능한 조건과 한계를 제시하였다.
