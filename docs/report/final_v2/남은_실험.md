### 1.2 공란 3~9 — Accel-Sim과 같은 6개 조건의 성능 시뮬레이터 예측

조건은 H_q=32, H_kv=8, d=128, fp16이고 B와 L만 바꾼다(`grids/sim_smoke.yaml`과 같은 헤드 구성). 실측 µs와 Accel-Sim µs는 `docs/setup/accelsim_4090_gate_report.md`의 표에서 가져왔다.

```bash
cd /root/sunjae/gpu_graduation/kernelscope
.venv/bin/python - <<'EOF'
from kernelscope.workload import Workload
from kernelscope.model.machine import MachineSpec
from kernelscope.model.params import ModelParams
from kernelscope.model.predict import predict
m = MachineSpec.from_json("machines/rtx4090.json"); p = ModelParams.from_json("models/rtx4090.json")
real = {("fa2",1,1024):63.584, ("fa2",1,8192):494.336, ("fa2",16,1024):64.303,
        ("flashdecoding",1,1024):10.016, ("flashdecoding",1,8192):27.456, ("flashdecoding",16,1024):38.2235}
for (k,B,L), r in real.items():
    q = predict(k, Workload("decode",B,1,L,32,8,128,"float16",True), m, p, "warm")
    print(k, B, L, f"{q.time_us:.1f}", f"{abs(q.time_us/r-1)*100:.1f}%")
EOF
```

**미검증 시험값(2026-10-28 로컬 실행, 아직 verify에 등록하지 않음):**

| 조건 | 실측 µs | Accel-Sim µs | 시뮬레이터 µs (warm) | 시뮬레이터 오차 | 참고: cold 예측 µs |
|---|---|---|---|---|---|
| FA2 B=1, L=1K | 63.6 | 67.5 | 61.0 | 4.1% | 82.8 |
| FA2 B=1, L=8K | 494.3 | 515.9 | 460.1 | 6.9% | 573.0 |
| FA2 B=16, L=1K | 64.3 | 109.7 | 61.0 | 5.2% | 83.2 |
| FlashDecoding B=1, L=1K | 10.0 | 15.5 | 10.8 | 8.0% | 22.5 |
| FlashDecoding B=1, L=8K | 27.5 | 73.6 | 23.3 | 15.0% | 56.6 |
| FlashDecoding B=16, L=1K | 38.2 | 116.8 | 37.2 | 2.7% | 91.8 |

warm 기준 오차는 2.7~15.0%(중앙값 약 6%)이다. 같은 조건에서 Accel-Sim의 오차는 4~206%이다.

보고서에 넣기 전에 정할 것:
1. **캐시 조건.** gate 보고서에 "Real-HW measurement follows warm-up"이라고 적혀 있어 warm 예측과 비교했다. cold로 계산하면 오차가 16~140%로 벌어지므로, 표 10이나 각주에 "warm 기준"을 반드시 적는다.
2. **학습 표본 여부.** FA2 B=1·L=8K는 보정 격자 안에 있다(`kernelscope/model/validate.py`의 `TRAIN_B=(1,4,16,64)`, `TRAIN_L=(512,2048,8192,32768)`). 나머지 L=1K 다섯 칸은 학습에 쓰지 않은 보간 조건이다. 각주 한 줄로 밝힌다.
3. **해석 범위.** 성능 시뮬레이터는 같은 GPU의 실측으로 보정했고, Accel-Sim은 보정하지 않은 사이클 시뮬레이터다. 따라서 "Accel-Sim보다 정확하다"가 아니라 "실측으로 보정한 시뮬레이터가 같은 조건에서 x% 이내"로 쓴다. 현재 본문 문장("선택 정책에는 실측으로 보정한 성능 시뮬레이터를 사용하였다")과 맞는 표현이다.
4. **verify 원본.** 실측 µs 원본은 연구실 호스트의 Accel-Sim 결과 폴더에 있다. verify 항목은 커밋된 `docs/setup/accelsim_4090_gate_report.md`의 표를 원본으로 삼거나, 연구실 호스트의 결과 요약을 `demo_data/`로 옮겨서 만든다.

## 2. 선택 실험 (보고서 보강, 생략 가능)

권장 순서: **(a) > (e) > (d) > (b) > (f) > (c)**. 소요 추정은 `docs/handoff/2026-10-25-overnight-report.md` §5·§6을 따른다.

### 2.1 GPU 필요 (연구실 RTX 4090, 합쳐서 약 30분)

**(a) 고정 분할 8, 혼합 32K의 이상치 재측정 — 약 3분, 가장 추천**
- 이유: 표 14의 고정 8 값 `1.644*`가 반복 1 하나(TPOT 45.17 ms, 다른 반복 약 34 ms) 때문에 낮아졌다. 원인은 확인하지 못했다. 이 반복을 빼면 1.811배다(`docs/experiments/2026-10-24-final-evidence.md` §1).
- 실행: 원래 대기열 스크립트 `../kernelscope/results/overnight_20261024/gpu_queue/01_fixedsplit.sh`(연구실 호스트)의 혼합 길이 부분을 그대로 쓰는 것을 우선한다. 같은 규약을 직접 실행하면 다음과 같다.
  ```bash
  .venv/bin/python -m kernelscope.cli serve run --model Qwen/Qwen3-4B-Instruct-2507 \
    --scenario scenarios/graduation_ragged.yaml \
    --policy heuristic --policy table:demo_data/dispatch_paged_cold.csv --policy fixed:8 --policy fixed:16 \
    --kv-gib 10 --repeats 3 --warmup-runs 1 --policy-cache keep --seed 0 \
    --out ../kernelscope/results/serve_4090/fixedsplit_rerun_<날짜>/ragged
  ```
- 규칙: 기존 `fixedsplit_20261024` 결과는 지우지 않고, 새 폴더에 따로 남긴다. 30초 간격 `nvidia-smi` 기록도 같이 남긴다.
- 보고서 반영: 표 14의 각주를 "재측정 x.xxx배"로 바꾼다. 새 번들에 대한 verify 항목도 추가한다.

**(b) 트레이스 e2e의 미분류 분기 9곳, 교사 강제 분류**
- 이유: table 정책의 분기 10곳 가운데 1곳만 분류됐다(bf16 1 ulp 동점). 나머지 9곳(model은 7곳)은 교사 강제 구간(처음 400 decode 호출) 밖이라 미분류다(final-evidence §7). 모두 동점으로 분류되면 4장 사) 한계 문장을 약하게 쓸 수 있다.
- 실행: `scripts/check_policy_numerics.py`를 `--scenario scenarios/trace_azure_conv_i550_n300.yaml`로 돌리되, `--logit-steps`를 분기 지점 이후까지 늘린다. 이어서 `python -m scripts.classify_divergence`로 분류한다. 원래 실행은 `gpu_queue/03_trace_e2e.sh`(연구실 호스트)에 있다.
- 주의: 교사 강제 진단은 성능 측정이 아니다. CPU로 로짓을 복사하므로 시간 값은 쓰지 않는다.

**(c) vLLM CUDA graph 모드에서 실제로 쓰이는 `num_splits` — 우선순위 최하**
- 보고서는 이 값을 주장하지 않는다(표 16은 attention GPU 시간 분해만 쓴다). vLLM 소스(`v1/attention/backends/flash_attn.py:771-773`)를 따라가 로깅해야 하므로 생략을 권장한다.

### 2.2 GPU 없이 가능 (로컬 WSL2, 각 2~4시간)

**(d) 모델×GPU 분할 없음 임계 표 (P2c)**
- 이유: "다른 GPU·모델에서도 같은 문제가 생기는가"라는 질문에 답한다. 지금은 RTX 4090(SM 128)과 H_kv=8만 있다.
- 방법: `kernelscope/model/geometry.py`의 `num_splits_heuristic`(flash-attn 2.8.3 이식)을 이용한다. decode에서 B·H_kv ≥ 0.8·2·SM이면 분할하지 않는다. 이 조건으로 (H_kv, SM 수) 조합마다 문턱 B를 계산해 표로 만든다. SM 수는 제조사 사양을 출처로 단다.
- 보고서 반영: 3장 가) 또는 4장 다) 뒤에 표 하나. 실측이 아니라 공식 계산이라고 밝힌다.

**(e) 혼합 정책 δ 민감도 (P2d)**
- 이유: "δ=0.2는 임의로 고른 값인가"에 답한다.
- 방법: `scripts/evaluate_hybrid.py`가 δ ∈ {0.05, 0.10, 0.20, 0.50}의 leave-one-out 손실을 이미 계산할 수 있다. 실행 결과를 표로 정리하고 verify 항목을 추가한다. 기록이 이미 있으므로 새 측정은 필요 없다.
- 보고서 반영: 표 13 옆에 δ 열 또는 짧은 문단.

**(f) Mooncake 긴 문맥 트레이스 재생 (P2b)**
- 이유: 긴 문맥 서비스의 길이 분포에서 문제 빈도를 보인다. 지금은 Azure·BurstGPT만 있다.
- 방법: 트레이스를 내려받아 `scripts/traffic_replay.py --trace ...`로 재생한다. 입력 형식이 맞는지 먼저 확인한다. GPU 없이 얻을 수 있는 것은 예측 손실뿐이고, 실측 검증에는 GPU가 필요하다.
- 보고서 반영: 4장 다) 부하 분석에 한 줄 추가. 예측값임을 밝힌다.
